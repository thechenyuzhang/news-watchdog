## What to read / what to watch

**This week's theme:** agents that approve too much, chase stale TODOs, and hide their mistakes — and how to put judgments (not whole decisions) in a small model.

1. **Bas Brekelmans (Microsoft), “Nine engineers, 1,211 pull requests in a day: Lessons from building Copilot Cowork”** (Nov 2) — essay/playbook. **New creator.**
   - Empty repo Jan 13 → worldwide GA Jun 16; agents wrote most of the code. On Oct 21, nine engineers merged 1,211 PRs. Then they moved the live runtime from Python to Rust: p50 time-to-first-token 7.9s → 2.7s (partly from taking the agent loop out of the container).
   - Six practices: markdown spec before any code; narrow agents in credential-free containers behind a trusted host; every check reports how many files it scanned *and* ships with a test that forces it to fail (`| tail` had been swallowing exit codes); team rules live in the repo; strict crate roles (implementation-to-implementation deps 216 → 0); automated “factory” loops with keep/revert rules, attempt limits, and a revert-the-fix gate so a new test must fail without the change. Week of Oct 12: 4,581 PRs merged.
   - Why now: the most concrete large-org factory-harness write-up this week, and it was not in prior briefs.

   ([Microsoft Command Line](https://commandline.microsoft.com/how-we-built-copilot-cowork-python-to-rust-migration/))

2. **Sam Saccone & Madhuri Garikapati (Google), “Agent Distraction”** (Nov 6) — data-backed eng blog. **New creator.**
   - Telemetry across hundreds of millions of agent steps: stale `TODO(bug/…)` comments appeared in 13% of file-reading sessions; agents acted on them in 6% of encounters, and 83% of those actions were unprompted. Of the unprompted detours, 41% chased already-closed tickets and 57% expanded into still-open bugs nobody asked about.
   - Controlled regression: a detour added ~70% more steps, ~77% more tokens, and ~105% more wait time. Cleanup agents that check ticket *and* file history before deleting a TODO removed thousands over six months, with >95% reviewer acceptance.
   - Why now: pairs with the Claude Code permissions story — leftover context is now a cost center.

   ([Google Developers Blog](https://developers.googleblog.com/agent-distraction/))

3. **Allie Laabs (TypeSafe), “Don't Call It a Decision Model”** (Nov 3) — design essay.
   - Don't stuff a whole business decision into one Jev `criteria` blob (“prompt gymnastics”). Split it into small judgments Jev makes (`wants_money_back 0.99`) and facts your code computes; code combines them into the decision. Slogan: “Jev makes judgments, code makes decisions.”
   - Payoff: traces that show whether the *judgment* or the *rule* was wrong, and new outcomes don't disturb judgments you've already validated. Coding agents, the post notes, are pretty good at helping you find those atomic judgments.
   - Why now: first-time in these briefs; lands next to Drex's open challenge and Saturday's Hightouch cascade.

   ([TypeSafe](https://typesafe.ai/blog/dont-call-it-a-decision-model))

4. **Sean Goedecke, “LLMs are terrible at designing AI systems”** (dated Nov 8) — short essay. **New creator.**
   - Coding agents often invent doomed symbolic machinery (a memory-contradiction solver; regex card-sorting) instead of just calling a model. His working theory: they are weak at software design, not only held back by pre-LLM training data. Advice: steer them toward a model call — or a decision model — for anything semantic.

   ([seangoedecke.com](https://www.seangoedecke.com/llms-are-terrible-at-designing-ai-systems/))

5. **Ben Holmes (Warp), “Your AI Agent Is Hiding Its Mistakes From You”** (AI Engineer NYC, uploaded Nov 6) — 19-minute talk. **New creator.**
   - Agents quietly work around broken instructions (stale test docs → extra minutes of port-probing with no visible failure). Fix: store full traces, grade them with markdown rubrics, and let a daily agent propose PRs back to skills/config. Demo: “Skill Doctor” over local Claude Code and Codex history.

   ([YouTube](https://www.youtube.com/watch?v=pz74r-4dGfQ))
