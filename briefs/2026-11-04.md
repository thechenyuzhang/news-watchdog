## What to read / what to watch

**This week's theme:** agents run like an engineering org. Three first-person reports (64 PRs in one morning, 1,711 merged PRs in five weeks, 200+ PRs a month) all say the bottleneck has moved to verification, approvals and human attention.

1. **Neil Kakkar (guest essay, The Pragmatic Engineer), "How software engineering is changing: a tale of two eras"** (Nov 3, long read, **New creator**; won Pragmatic Engineer's essay challenge).
   - At Tano he ships 200+ PRs a month vs 8–20 at PostHog, running 3–5 Claude Code workstreams. Code review is optional once onboarded: a CI review agent runs on every PR; median time to merge under an hour; revert rate 6x lower because they fix forward.
   - Named failures: an agent assumed every currency has 100 minor units; a blocking index migration on a 25 GB table halted ingestion; a migration without guardrails paid creators twice.
   - New constraints: thrashing, bus factor of 1 (mitigated with AGENTS.md), burnout by 3 PM, design sameness, and plan limits (he estimates $8K+/month at API rates).

   ([Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/how-software-engineering-is-changing))
2. **Miguel Ríos Berríos (Parcha founder), "Running coding agents like engineering orgs"** (Oct 29, X article, **New creator**, found one hop from Vinny Carpenter).
   - Opus 5.5 tech leads staff Opus/Sonnet/Haiku 5.5 "engineers." Over 5 weeks: 2,896 agents, 1,711 of 2,001 PRs merged, his share of messages fell from 1 in 27 to 1 in 150.
   - Emergent behavior: a staff-engineer lane became the de facto gate (39 of 446 planted bugs slipped through); agents invented lock files and a "safe-send" tool; one lead "fired" a manager agent stuck in a sleep loop.
   - Bottleneck: PRs waited a median 4.5 hours for his first approval. CI and review bills "went through the roof."

   ([X article mirror](https://nitter.gq/MiguelriosEN/article/2115891556251234339); canonical X URL not fetched)
3. **Vinny Carpenter, "64 PRs Before Lunch"** (Nov 4, ~15-min essay, **New creator**). A tech-lead agent ran 11 workers across 3 repos and merged 64 PRs in ~2 hours; of 25,882 added lines, only 3,817 were app code (the rest fixtures and tests). An evening readiness review still said "not ready to deploy as a whole." Lessons: "merged PRs are output," and the lead posted reviews from his own GitHub account, an "agent wearing your badge." ([vinny.dev](https://vinny.dev/blog/2026-11-04-64-prs-before-lunch/))
4. **Dominic Plouffe, "An eBay MCP server spends 40% of my context window on its tool list"** (Nov 4, 6-min measured test; Layer 1). He measured tools/list cost for 22 setups from 17 MCP servers: ebay-mcp 81,255 tokens (40.6% of 200K); github-mcp-server 23,139 with all toolsets vs 5,896 filtered read-only; a sensible "7% stack" costs 14,017 tokens; an 11-server kitchen sink takes 69.3%. Do Monday: delete unused servers, set filters, measure. ([dplouffe.ca](https://www.dplouffe.ca/2026/11/04/mcp-context-cost-servers-worth-keeping/))
5. **Latent Space: Jacob Lauritzen (CTO, Legora), "Building Legal Agents When You Can't See the Data"** (Nov 2, 67-min podcast; Layer 1). Evals built in simulated "worlds" (e.g. a 10,000-file data room) by 3 engineers and 3 lawyers because client traces are off-limits; citation accuracy went from 70% to 99% after one model release; "drafting is a search problem." ([Latent Space](https://latent.space/p/building_legal_agents_when_you_can_t_see_the_data_-_jacob_lauritzen_cto_of_legora/))
6. **Open Athena (David Hall), "There is no posttraining data commons"** (Oct 15; HN front page Nov 3–4, **New creator**). Pretraining eats documents; post-training eats tasks (world + intent + tools + grader), and no open commons of tasks exists. Evidence: SWE-bench went ~90K PRs → 2,294 tasks; TaskTrove discarded >90% of 5,000 Java tasks. ([openathena.ai](https://openathena.ai/blog/there-is-no-posttraining-data-commons/))
7. **Simon Willison, "Qwen 3.8 27B on my laptop can interpret model weights, too"** (Nov 3, HN 685; **delta** on Nov 3's pick). Local Qwen 3.8 27B named Pac-Man, Pong and Breakout from raw weights (46 min–1h05m each), failed on Freeway; Kimi K3.1 Pro via OpenRouter got Breakout in 9m41s. He separates no-tool reading from tool-assisted editing and is "not ready to declare that the age of source code is over." ([simonwillison.net](https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/))
8. **Ben Stolovitz, "How I use AI (Oct 2026)"** (Oct 31, HN 227, **New creator**). Salesforce AI Research engineer, ~$3K/month on tokens, 5–6 agents in separate worktrees. "Writing code is solved," taste isn't: he replaced ~4,000 lines of vibe-code with a few hundred by hand. AI is still a poor research collaborator. ([stolovitz.com](https://ben.stolovitz.com/posts/how-use-ai-oct-2026/))
