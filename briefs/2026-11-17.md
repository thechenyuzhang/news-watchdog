## What to read / what to watch

**Today's theme:** verification is the new bottleneck, from coding agents to proofs to the security perimeter.

1. **Addy Osmani (Anthropic), "How the Claude Code team thinks about verification"** (Nov 16, essay; HN 103). About 90% of Claude Code's code is written and reviewed by Claude. Takeaways:
   - Invest in **E2E, property and differential tests**, and put a `verify` skill in `.claude/skills/` so the agent boots and drives the real app.
   - After **three failed fix rounds**, the agent stops and calls a human.
   - A 39-item reliability checklist is keyed to triggers readable from a diff, so only 3–10 items run per change.
   - Adding a second reviewer is worse than tuning one reviewer with a REVIEW.md that's read from the *base* branch: **"changes can't modify their own checks."**
   - Commits are stamped with how they were verified (including "none"), and new gates start in observe mode before enforcement.
   - A separate grader added up to 10 points of task success.
   
   Copy this playbook directly. ([claude.dev](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/))

2. **Dan Luu, "Test/verification technique effectiveness with Astra"** (Nov 16, eval writeup; HN 78). *2nd high-signal hit (first: Oct 2026 "We should be more ambitious…", HN 893), so he's promoted to the standing radar today.*
   - On the Zstd-from-RFC eval, GPT‑6 Astra reaches full holdout correctness >99% of the time for ~$1 at medium effort, versus 63–77% for $3.50–$5.50 with GPT‑5.6 Sol. The eval is now saturated.
   - On harder tasks (IMAP, then Pandoc across ~14 turns; ~$90K of runs), many testing techniques now **beat the "Default" condition**, whereas with Sol almost none did. Structured fuzzing now finds real bugs. TDD seems to generalize worse.
   - He warns the error bars are wide and that the viral "technique X wins" tweets are usually overstated.
   
   ([danluu.com](https://danluu.com/astra-testing/))

3. **Zane Lackey (a16z), "The Dream of the 1990s Is Alive Again in Cybersecurity"** (Nov 16, essay). Fresh institutional piece. Argues that AI has collapsed the cost of offense, so 2026 feels like 2002:
   - Expect **"Worms 2"**, but aimed at **stealing inference API keys**, which are displacing crypto mining as attackers' payoff.
   - Expect the "Windows XP first-day" patching problem across all software, so enterprises will move to near-automatic patching.
   - Expect a new generation of hardened infrastructure products.
   
   Advice: continuous no-scope red-teaming, detection and response tuned to AI speed, and a rebuilt stack (agent identity: Keycard; supply chain: Socket). Read it next to the CA v. OpenAI suit and the Optimizely attack. ([a16z.news](https://www.a16z.news/p/the-dream-of-the-1990s-is-alive-again))

4. **Alperen Keles, "Formal Verification Is Not Verifiable"** (Nov 13, essay; HN 147). **New creator.**
   - Testing produces a reviewable object (a bug report). Formal verification makes "forall" claims whose definitions, models and provers are hard to check.
   - Say "formally verified X properties of Y", never "formally verified software". Binary-level verification shrinks the trusted base but doesn't eliminate it.
   - He's optimistic that machine proofs can cover single-threaded program properties expressible as property tests by ~2030.
   
   Pairs with yesterday's Xena/Lean piece. ([alperenkeles.com](https://alperenkeles.com/posts/formal-verification-is-not-verifiable/))

5. **Latent Space (Richard MacManus), "Cloudflare Joins the Jevolution and Labels Itself a Neolab"** (Nov 17, interview). Named-watchlist item (Jev).
   - Cloudflare's Michelle Chen says Jev's September launch was "the east wind". Cloudflare built **Clef**, a Jev-style System One decision model, in **two weeks**, versus TypeSafe's two years, and credits TypeSafe for the API schema.
   - **Clairic** is a new "extraction" model class that pulls typed values from unstructured input in one forward pass.
   - Next could be post-trained reasoning LLMs, but not from-scratch pretraining. Part of the motivation is de-risking away from closed models like Jev and from Chinese open weights.
   
   Competitive read for anyone in the decision-model set. ([Latent Space](https://latent.space/p/cloudflare/))
